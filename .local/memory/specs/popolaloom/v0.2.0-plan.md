## 0. 一页摘要 (TL;DR)

### 0.1 v0.2.0 是什么 (1 段定义)

**PopolaLoom v0.2.0 是从 "in-process 派发脚手架" 升级到 "spec §3.1 L2 真 daemon + LangGraph plan 调度 + ArkTower 真持久化 + MCP IDE 入口" 的关键跃迁版本**: 把 v0.0.1 的 Popolad in-process 类拆成"独立 popolad daemon 进程 (asyncio + uvicorn UDS) + httpx 客户端 CLI"的标准 client/server 架构, 让 LangGraph StateGraph 取代当前 in-process Popolad.dispatch 主循环, 让 ArkTower TaskService + EventBus 真正承载任务持久化与跨子系统事件总线, 让 popolaloom-mcp 通过 stdio 把 7 个 dispatch verbs 暴露给 Cursor/Claude IDE Agent, 同时落 spec §3.4.1 五例自验证场景中的 S1 (跨进程崩溃恢复) + S3 (递归派发隔离) 两条作为 Iter-2 闭环的回归基线; 09 §5 锁定的 14 个 Iter-1 issue 中, P0 5 条全部关闭, P1 7 条至少关闭 6 条, 让 v0.2.0 成为 Phase 1 R4 路线"M1 真 daemon + M2 真图引擎 + M3 真任务池 + M4 IDE 入口 + M5 自验证基线" 5 个里程碑同时落地的"基础设施完整版"。

### 0.2 5 大里程碑 (M1-M5, 每个 1 行)

- **M1 · Real daemon 进程化**: popolad 成为独立 OS 进程, CLI 通过 unix socket RPC 跨进程调度, 关闭 R-001 (出处: 09 §5 R-001 + spec §3.1 L2)
- **M2 · LangGraph 真接入**: dispatch 路径走 StateGraph + SqliteSaver, dev↔test Gen-Verifier subgraph demo 落地, HITL `interrupt()` 占位测试通过, 关闭 R-003 (出处: ADR-0002 §2.1 + 09 §5 R-003)
- **M3 · ArkTower 真持久化**: TaskService.create_task 替代当前 fake `_maybe_create_arktower_task`, EventBus 订阅 TASK_TRANSITION_EVENT, 关闭 R-004 (出处: ADR-0001 §2.2 + 09 §5 R-004)
- **M4 · MCP stdio + 7 verbs**: popolaloom-mcp 暴露 7 dispatch verbs 给 Cursor/Claude IDE 通过 mcp.json 配置, 关闭 spec §3.2 row "popolaloom-mcp" 0% 现状 (出处: spec §3.2 + impl-plan Day 4)
- **M5 · 自验证 S1+S3 基线 + Iter-2 闭环回归**: tests/self_bootstrap/ 目录落 S1 + S3, 跑 Iter-2 闭环 (popola dispatch + cursor + 自评), nines 分 ≥ 0.85 (相对 v0.0.1 估算 0.32 的 2.6x 跃升), 关闭 R-002 (出处: spec §3.4.1 + 09 §1.3 + 09 §5 R-002)

### 0.3 与 v0.0.1 的关键差异 (3-5 条)

1. **进程模型**: v0.0.1 = in-process Python 类 (Popolad 由 cli.main 通过 lru_cache 实例化, daemon 与 CLI 共享一个解释器); v0.2.0 = OS 级独立 daemon 进程 (`python -m popolaloom.daemon`) + UDS RPC (~/.popola/popolad.sock) + CLI httpx.AsyncClient 客户端
2. **持久化**: v0.0.1 = 仅 NDJSON event log + in-memory StateStore (重启丢光 in-flight task); v0.2.0 = NDJSON + ArkTower SQLite (TaskService 持久化) + LangGraph SqliteSaver (super-step checkpoint) 三轨, popolad 重启可 rehydrate in-flight task
3. **图引擎**: v0.0.1 = 0 行 LangGraph 调用 (依赖在 pyproject 但未使用); v0.2.0 = 单节点 StateGraph + SqliteSaver + Gen-Verifier subgraph demo + HITL interrupt() 占位
4. **IDE 入口**: v0.0.1 = 仅 popola CLI (6 子命令), 没有 Cursor/Claude IDE Agent 入口; v0.2.0 = popolaloom-mcp stdio server + 7 dispatch verbs + mcp.json 模板
5. **测试基线**: v0.0.1 = 18/18 测试 PASS 但 0/5 self-bootstrap 覆盖 + 0/12 NFR 量化 assertion; v0.2.0 = ≥ 50 测试 / ≥ 75% 覆盖率 / 2/5 self-bootstrap (S1 + S3) / 至少 NFR-3 + NFR-5 + NFR-8 量化基线

### 0.4 验收门 (Definition of Done) 量化指标 5 条

1. **5/5 P0 修复**: R-001..R-005 全部关闭 (出处: 09 §5)
2. **6/7 P1 修复**: R-006..R-012 至少关闭 6 条 (R-010 systemd-run 全后端化可推迟为 v0.3.0)
3. **测试覆盖**: pytest 总数 ≥ 50, line coverage ≥ 75% (v0.0.1 基线 18 测试 + ArkTower 71% 类比目标)
4. **闭环回归**: Iter-2 闭环 (popola dispatch "用 nines + devola-flow 评估 popolaloom v0.2.0" --cli claude --wait) 新发现 issue ≤ 5 (说明 P0 修复有效)
5. **nines 自评**: PopolaLoom-nines runner 落地并跑出 ≥ 0.85 综合分 (v0.0.1 基线 ≈ 0.32, 出处: 09 §1.3 派发 agent 估算)

## 2. v0.2.0 范围

### 2.1 In Scope (本期必交付)

5 项核心交付, 与 09 §5 R-001..R-005 一一对应:

1. **真 daemon 进程化 (R-001 + R-005)**: popolad 成为独立 OS 进程, asyncio + uvicorn + UDS server; CLI 改 httpx.AsyncClient over UDS; popolad start/stop/status 子命令; popola attach 默认对未完结 task 隐式 follow 直到 terminal 事件
2. **LangGraph StateGraph + SqliteSaver + 最小 HITL (R-003)**: 单节点 StateGraph (dispatch -> spawn -> wait -> emit_terminal); SqliteSaver thread_id = task_id; dev↔test Gen-Verifier subgraph demo (3 节点, max_iter=2); HITL interrupt() 占位 + mock human reply 测试
3. **ArkTower TaskService + EventBus 真接入 (R-004)**: 注入 TaskService.create_task 替代 fake `_maybe_create_arktower_task`; 订阅 EventBus.TASK_TRANSITION_EVENT; 跑 ArkTower migration; popolad 重启可 rehydrate in-flight task
4. **MCP server (stdio) + 7 verbs (M4)**: popolaloom-mcp 用官方 mcp Python SDK + stdio transport; 7 verbs (popola_submit / popola_list / popola_status / popola_attach_stream / popola_supply_feedback / popola_cancel / popola_inject_subtask); form-mode elicitation 占位; mcp.json 模板
5. **Self-bootstrap S1 + S3 + Iter-2 闭环 (R-002 + 验证 5 条 P0)**: tests/self_bootstrap/test_s1_crash_recovery.py + test_s3_recursive_dispatch.py; 修剩余 P1 (R-006/R-007/R-009/R-012); 跑 Iter-2 闭环对比 nines 分

> **附加修复 (并入 5 项交付的隙裂)**: R-006 (Stage A 顺手加 _event_logs_lock); R-007 (Stage A 改 join 30s + stream.truncated); R-008 (Stage A KeyError emit ghost_exit + arktower 失败返 None); R-009 (Stage E 拆 CommandBuilder + Runtime Protocol); R-011 (Stage C 改 fd-held write + benchmark); R-012 (Stage E 加 --cli-flag); R-013 部分 (Stage A 清理双重 singleton); R-014 部分 (Stage A `_task_summary` 统一返回 shape, --events-dir 透传)。

### D2.1 · daemon 进程模型

| 候选 | 利 | 弊 | 推荐 |
|---|---|---|---|
| asyncio (单进程多 task) | 与 LangGraph async 节点天然兼容; 单解释器内存共享; uvicorn ASGI 标准 | 多 CPU 无法利用 (GIL); 一个 task hang 整个 loop hang | ✅ |

| multiprocessing | 真并行 + 进程隔离 | IPC 复杂, ArkTower SQLite 多进程写需要 WAL 协调 | |
| aiofiles + asyncio | 文件 IO 不阻塞 loop | 仅解决文件 IO, 进程模型本身仍是 asyncio | |

## 4. v0.2.0 工作分解 (5 个 Stage / 共 ~5.5 工作日)

### Stage A · Real daemon 进程化 (Day 2-3, ~1.5 day)

**目标**: popolad 变成独立 daemon 进程, CLI 通过 unix socket RPC 连接, 顺手清理 R-006 / R-007 / R-008 / R-013 / R-014 几条隙裂修复。

#### 子任务

- **A1**: `popolad/main.py` 进程入口 + asyncio + uvicorn UDS server
  - 内容: `python -m popolaloom.daemon` 启动后, asyncio.run(main()) 创建 uvicorn config (uds=str(socket_path), app=create_app()), 信号处理 SIGTERM/SIGINT 干净退出, 写 PID 文件 (~/.popola/popola.pid)
  - 引用: spec §3.1 L2 + impl-plan Day 1 子任务 1
- **A2**: `daemon/rpc.py` FastAPI app + 7 endpoints
  - Endpoints: POST /dispatch / GET /status/{task_id} / GET /list / GET /attach_stream/{task_id} (SSE 流式) / POST /cancel/{task_id} / GET /probe / GET /health

  - StateStore 内部仍带 _lock 与 in-memory dict (作为 hot cache), 但 register/update 同时调 arktower TaskService.create_task / advance_task; daemon 启动时从 ArkTower SQLite rehydrate active task → in-memory dict
  - 与 Stage C 的 repository.py 协同 (实际 TaskService 注入由 C1 完成, A3 仅准备 hook 点)
- **A4**: `cli/main.py` 改用 httpx.AsyncClient over UDS 调用 daemon
  - 关键: `httpx.AsyncClient(transport=httpx.AsyncHTTPTransport(uds=socket_path))`; CLI 不再 import Popolad 类; 删除 `_get_popolad` lru_cache; daemon-down 时给清晰错误 ("popolad not running, run `popolad start` to start it")

  - v0.2.0 实现简化: 仅 `popolad start` (subprocess.Popen(["python", "-m", "popolaloom.daemon"], start_new_session=True)) + `popolad stop` (read PID file + kill) + `popolad status` (检查 socket + PID)

  - R-013 (部分): 删除 daemon/server.py module-level _default_popolad + cli/main.py _get_popolad lru_cache (CLI 改 httpx)
  - R-014 (部分): 提取 `_task_summary(handle, *, full)` 统一返回 shape; cli/main.py list-cli status 用 Rich Text 对象代替字面 `[available]`; cli/main.py dispatch / Popolad 透传 `--events-dir`

- **modify**: `src/popolaloom/daemon/server.py` (StateStore 持久化 hook + KeyError ghost_exit + arktower 失败 None + 删除 module-level singleton + _event_logs 加锁), `src/popolaloom/daemon/state.py` (rehydrate 接口), `src/popolaloom/daemon/supervisor.py` (join 30s + stream.truncated event)
- **modify**: `src/popolaloom/cli/main.py` (改 httpx + attach 隐式 follow + --events-dir + --cli-flag KEY=VAL 占位); `src/popolaloom/cli/__init__.py` (注册 popolad 子命令组)

- **不动**: `src/popolaloom/adapters/*` (Stage E 才拆)

#### Acceptance criteria

- `popolad start` 后, 在另一个 terminal `popola dispatch ... && popola status <id>` 跨进程能看到任务 (修 R-001)
- pytest tests/ 维持 100% 通过, 测试数从 18 → ≥ 30 (新增 ~ 12 测试)
- popola attach `<id>` 对未完结 task 自动 follow 直到 terminal event (修 R-005); `--no-follow` 显式可以保持旧行为
- 大输出场景 (mock subprocess 输出 10 万行 stdout) join 30s 内完成或 emit `stream.truncated` (修 R-007)
- KeyError 路径在测试中被触发 (mock unknown task_id) → event log 出现 `state.ghost_exit` (修 R-008)
- daemon/server.py 不再有 `_default_popolad` 模块变量, cli/main.py 不再有 `_get_popolad` lru_cache (修 R-013 部分)

#### 风险

- **asyncio + threading 双向通信 (subprocess thread 写 NDJSON, asyncio attach stream 读)** 需仔细设计 backpressure: 推荐 `asyncio.Queue + run_in_executor`, attach SSE stream 用 `await queue.get()` + 周期 yield; 备用方案: `aiofiles` 异步读 NDJSON 文件末尾 (tail-f 模式)
- **ArkTower TaskService 创建 task 失败的回滚路径** (R-008 修复要求): A3 设计 hook 点, 实际接入 C1 完成; 若 C1 延迟则 A3 先用 in-memory 保留行为不变, 仅 marker hook
- **httpx UDS transport 兼容性**: httpx ≥ 0.24 才有 AsyncHTTPTransport(uds=...); pyproject.toml 锁版本

### Stage B · LangGraph StateGraph + SqliteSaver (Day 3, ~1 day)

**目标**: dispatch 路径走 LangGraph, dev↔test Gen-Verifier 子图 demo, HITL `interrupt()` 占位; ADR-0002 落地兑现; 关闭 R-003。

#### 子任务

- **B1**: `daemon/graph.py` 单节点 StateGraph 定义 (dispatch -> spawn -> wait -> emit_terminal)
  - State schema: `class TaskState(BaseModel): task_id: str; cli: str; cwd: Path; prompt: str; status: Literal["pending","running","completed","failed","interrupted"]; subprocess_pid: int | None; events_count: int; final_message: str | None; error: str | None`
  - 节点: `dispatch` (调 ArkTower TaskService.create_task) → `spawn` (调 Supervisor.spawn) → `wait` (await proc.wait + 同步事件) → `emit_terminal` (写 task.completed / task.failed)

| **RV2-2** | ArkTower TaskService API 不稳定 (上游 0.1.0 仍在迭代, 每天 4 PR 节奏, 出处: 08 §1.2) | Major | 40% | 锁 commit hash `467a087` (ADR-0001 §3.2) + 周对照 main 跑 ArkTower 293 测试回归 + sibling-intent issue (Q-NEW-1) 立刻发起; 若 PRH 引入 breaking change, PopolaLoom 代码 fork commit 同步 |

| **RV2-5** | Iter-2 闭环又找到 ≥ 10 新 issue (说明 P0 修不够 deep, P0 修复时引入新隐藏债) | Critical | 25% | 进入 Iter-3 而非发版; v0.2.0 不启用 auto-merge gate (v0.4.0 才启); Iter-2 闭环失败时, 回到 §4 Stage E 重跑 + 把新 issue 加到 R-015..R-024 队列; nines 分 < 0.85 时 DoD 阻断 |
| **RV2-6** | tests/self_bootstrap/test_s1_crash_recovery.py 在 CI 不稳定 (CI runner 上 daemon 启动 + UDS + ArkTower SQLite + LangGraph SqliteSaver 协调 3 个进程边界, race 条件易触发) | Major | 35% | mark `@pytest.mark.slow` + `@pytest.mark.requires_real_daemon`; 本地必跑, CI 用 `pytest -m "not slow"` 默认跳过, 每周一专门 `pytest -m slow` 跑回归; 用 `tmp_path` 做隔离 socket / sqlite, 确保多 test 不串扰 |
