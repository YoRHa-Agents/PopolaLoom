## 0. 一页摘要 (TL;DR)

### 0.1 v0.4.1 是什么 (1 段定义)

**PopolaLoom v0.4.1 是把 v0.4.0 GA 的 Lark 通道从 "仅 HITL 触发时主动发卡" 升级到 "任务终态 + ghost-exit + skill-missing 全谱主动通知 + 修补 `task.canceled` 不发射的潜伏契约 bug + 在 daemon 启动时自动接起 LarkSupervisor → LarkListener 双向链路" 的窄域 minor 补丁版本**: 它不动 [spec §3.2](spec.md) 9 模块的覆盖率分布 (lark 模块从 ~70% → ~85%, 其他 8 模块持平), 不引入新 ADR, 不调整 [`pyproject.toml`](../../../../pyproject.toml) 依赖图, 仅在 `src/popolaloom/lark/{card_templates.py,notifier.py,__init__.py}` + `src/popolaloom/daemon/{server.py,supervisor.py,main.py}` 5 个文件内做最小侵入, 把 [research §D.3](../../research/v0.5.0-skill-install-lark-research.md) 实测的 "`send_lark_card` 在 `src/popolaloom/daemon/` 0 生产调用点" 这条 v0.4.0 隐疾, [research §D.4](../../research/v0.5.0-skill-install-lark-research.md) 的 "`_build_default_popolad` 没接 `LarkListener` / `LarkSupervisor`" 这条进程接线缺口, 以及 [research §D.5 + §F.3](../../research/v0.5.0-skill-install-lark-research.md) 的 "`task.canceled` 在 `src/popolaloom/daemon/` 0 处发射 / `evaluation/runner.py:325-331` 却消费它" 这条契约 bug 一并闭合, 让用户 [feedback_for_v0.4.0.md](../../../feedbacks/feedback_for_v0.4.0.md) 第 3 段诉求 "至少能够让 Popola Loom 在任务有完成或者有确认状态, 这种强需要人类交互的情况下, 能够主动通知到用户的机器人上" 可在 ~ 2 工作日内交付, 同时为下一个 milestone v0.5.0 (skill 交互面 + 多 IDE 安装) 提供一个干净的、不带潜伏 bug 的 daemon baseline。

### 0.2 4 大里程碑 (M-L1...M-L4, 每个 1 行)

- **M-L1 · `task.canceled` 真发射 + StateStore-aware supervisor (Option 2)**: `src/popolaloom/daemon/supervisor.py:188-227` 的 wait-thread 在 emit terminal event 之前先 consult `StateStore` 当前态, 若 `TaskState.CANCELED` 则 emit `task.canceled` (保留真 exit_code) 而非 `task.failed`, 关闭 [research §F.3](../../research/v0.5.0-skill-install-lark-research.md) 实证的契约 bug。
- **M-L2 · 5 张新卡 + `lark/notifier.py` 模块 + `kind` 参数复用 `send_lark_card`**: `src/popolaloom/lark/card_templates.py` 增 `build_completion_card` / `build_failure_card` / `build_canceled_card` / `build_cancel_escalated_card` / `build_skill_missing_card`, 新建 `src/popolaloom/lark/notifier.py` 暴露 `send_terminal_notification(popolad, task_id, terminal_state, exit_code) -> NotificationOutcome`, 复用 `send_lark_card` 的 retry/timeout/footer 机制 (per [research §E.2.1 + §E.2.2 + §E.2.3](../../research/v0.5.0-skill-install-lark-research.md))。
- **M-L3 · `_on_subprocess_exit` 钩子 + `_build_default_popolad` 启动接线**: `Popolad._on_subprocess_exit` (`src/popolaloom/daemon/server.py:867-905`) 在 StateStore update 成功之后调用 `lark.notifier.send_terminal_notification`; `_build_default_popolad` (`src/popolaloom/daemon/main.py:142-173`) 当 `is_lark_runtime_available() == True` 且 `LARK_HITL_TARGET_OPEN_ID` 存在时构造 `LarkSupervisor(LarkListener(...))` 接进 daemon 生命周期。
- **M-L4 · 端到端测试 + release-notes-v0.4.1.md + CHANGELOG 增项**: 新增 ~ 22 个 case (12 单元 + 6 集成 + 4 chaos, 1 `@pytest.mark.real_lark` smoke 默认 skip), 默认通道覆盖率不下降 (`fail_under = 91` 不动), `release-notes-v0.4.1.md` 记录 [research §G.2](../../research/v0.5.0-skill-install-lark-research.md) 5 项 must-have 全部交付, `CHANGELOG.md` 新增 [0.4.1] 段落对齐 Keep a Changelog 风格。

### 0.3 与 v0.4.0 的关键差异 (4 条)

1. **Lark 触发面**: v0.4.0 = 仅 5 个 HITL 触发 (`info_request` / `round_floor` / `approval` / `destructive_op` / `ambiguous_input`) 经 `hitl/renderers/lark.py` 出卡; v0.4.1 = 上述 5 个 HITL 触发 **+** 5 个新增任务生命周期触发 (`task.completed` / `task.failed` / `task.canceled` / `task.cancel_escalated` / `state.ghost_exit`) **+** 1 个 `skill.missing` 警告卡 (来自 `evolution/skill_inject.py:emit_skill_check_event`), 共 11 类卡片 (per [research §E.2.1](../../research/v0.5.0-skill-install-lark-research.md) trigger taxonomy 表)。
2. **`task.canceled` 事件可见性**: v0.4.0 = `cancel_task` 路径只 emit `task.cancel_escalated` (仅 SIGKILL 升级时, `src/popolaloom/daemon/server.py:683-690`), 而 supervisor wait-thread 看到 SIGTERM 退出码非零时 emit `task.failed`, 导致 `evaluation/runner.py:325-331` 消费的 `type_counts.get("task.canceled", 0)` 永远是 0 (per [research §F.3](../../research/v0.5.0-skill-install-lark-research.md)); v0.4.1 = supervisor wait-thread 在 emit 前 consult `StateStore.get_state(task_id)`, 若已是 `TaskState.CANCELED` 则 emit `task.canceled` + 真 exit_code (`-15` SIGTERM / `-9` SIGKILL / 进程自取消的 0), 其余路径不变。
3. **daemon 启动拓扑**: v0.4.0 = `_build_default_popolad` 仅装配 `build_command` / `_build_persistence_safely` / `Popolad` / `PopolaEventBusBridge` 4 件套 (per `src/popolaloom/daemon/main.py:155-172`), 入站 Lark 卡 / 群聊命令必须靠外部 harness 启动 listener; v0.4.1 = 当 `is_lark_runtime_available()` 且 `lark_target_open_id() is not None` 时, daemon 自带启动 `LarkSupervisor(LarkListener(events=("card.action.trigger_v1","im.message.receive_v1"), allowed_responders=lark_allowed_responders(), on_event=hitl_dispatch_callback))`, 其 lifecycle 与 daemon 主进程绑定 (daemon 退出 → supervisor stop → listener 子进程 SIGTERM)。
4. **Notification 默认开关 + 可观测性**: v0.4.0 = 无 (无终态通知); v0.4.1 = 5 个新 env var 控制开关 (`LARK_NOTIFY_ON_COMPLETED=1` / `LARK_NOTIFY_ON_FAILED=1` / `LARK_NOTIFY_ON_CANCELED=1` 默认 ON; `LARK_NOTIFY_ON_CANCEL_ESCALATED=0` / `LARK_NOTIFY_ON_SKILL_MISSING=0` 默认 OFF), 每张卡发完后 `lark.send.{ok,failed}` 仍按 v0.3.3 round-3 真 fixture 的格式落 NDJSON, `evaluation/runner.py` 的 `lark_send_total` / `lark_send_ok` 计数器自然包含终态通知 (向上兼容)。

### D4.1.1 · `task.canceled` 发射策略 (Option 1 vs Option 2 vs Option 3)

| 候选 | 利 | 弊 | 推荐 |
|---|---|---|---|
| **Option 1: `cancel_task` 自己 emit `task.canceled` 在 SIGTERM 之前** (`src/popolaloom/daemon/server.py:608-704`) | 实现简单 (1 行 `event_log.append("task.canceled", ...)` 在发信号前); supervisor wait-thread 不动 | 丢失真 exit_code (这时进程还没退出); 出现 race: 进程被 cancel 标记但又自己 exit_code=0 退出, supervisor 仍 emit `task.completed` → 出现两个终态事件 | |
| **Option 2: supervisor wait-thread 在 emit 前 consult StateStore** (`src/popolaloom/daemon/supervisor.py:188-227`) | 保留真 exit_code (SIGTERM=-15 / SIGKILL=-9 / 自取消=0); 单一 emitter (supervisor) 保持终态事件唯一性; 与 `state.ghost_exit` (R-008) 同模式 | 需要把 `state_store` 引用传进 supervisor (现有签名只有 `task_id` / `proc` / `event_log` / `cwd`); 测试要 mock state_store | ✅ |
| **Option 3: 双发射 + 去重逻辑 (cancel_task emit + supervisor 跳过 if state == CANCELED)** | 两端 fault-tolerant | 状态机复杂度爆炸; race window 期内 attach 客户端可能看到 inconsistent 序列; mutmut 难覆盖 | |

**推荐: Option 2 (StateStore-aware supervisor)**, 实施细节: `Supervisor.__init__` 增加 `state_store: StateStore` 形参 (现有 `Popolad` 在构造 Supervisor 时已经持有 `_state`, 改 1 行); wait-thread 在 `proc.wait()` 返回后, `try: state = state_store.get_state(task_id) except StateStoreError: state = None` (No Silent Failures: 异常 log + 走默认分支); 然后 `event_type = "task.canceled" if state == TaskState.CANCELED else ("task.completed" if exit_code == 0 else "task.failed")` (出处: [research §D.5 Option 2 + §G.2 #1 + §F.3](../../research/v0.5.0-skill-install-lark-research.md))。

### D4.1.4 · LarkSupervisor 启动时机 (eager vs lazy on first HITL)

| 候选 | 利 | 弊 | 推荐 |
|---|---|---|---|
| **eager: `_build_default_popolad` 启动时即构造 + start (env var 满足时)** | 入站 listener 立即就绪, 第一张 HITL / terminal 卡都能收到 ack 反馈; daemon shutdown 钩子可清理; 与 v0.3.0 D2.1 asyncio + uvicorn eager 启动风格一致 (per [v0.2.0-plan.md §3 D2.1](v0.2.0-plan.md)) | daemon 启动时多花 < 100ms 启动 LarkSupervisor 子进程 (v0.3.3 实测 NFR-1 cold start 0.815s, +100ms 仍 < 2s 目标) | ✅ |
