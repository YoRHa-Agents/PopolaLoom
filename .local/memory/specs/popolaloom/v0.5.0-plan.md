## 0. 一页摘要 (TL;DR)

### 0.1 v0.5.0 是什么 (1 段定义 — 引用 init_popola_loom.md "PopolaLoom 是纺织机 / 编织者")

**PopolaLoom v0.5.0 是把 v0.4.x "本机常驻 daemon + 真 nines 自评 + Lark 主动通知" 的服务层骨架升级到 "Skill 注册化 + 多 IDE 一键安装 + 自我健康自检" 的用户面交互完整版本**: 与 [init_popola_loom.md L1](../../../tasks/init_popola_loom.md) 锁定的 PopolaLoom 定位 ("正如名字所说的, 它应该是一个纺织机, 是一个编织者. 它要去调用或者唤起不同的 Agent 来去执行任务, 也就是它实际是一个更上层的编排者或编织者") 一致, 把 [.local/feedbacks/feedback_for_v0.4.0.md](../../../feedbacks/feedback_for_v0.4.0.md) 第 1 段 ("我需要你去开始完善交互面的事情, 就是如何作为一个 Skill 来做进行交互. 例如, 它应该可以支持通过 Skill 调用的方式, 将当前的对话和任务分发到一个 Agent 上, 也就是用 Popola Loom 去 Spawn 一个任务. 还支持呢, 去对这个任务进行一个 ID 的分配, 然后那也它可以去 Trace 到这个 ID 当前的进程, 甚至说 Attach 进去") 的诉求落到 5 项硬交付: (1) 从 [research §F.5 anomaly 2](../../research/v0.5.0-skill-install-lark-research.md) 实证的 `arktower @ file:///home/agent/reference/ArkTower` 硬路径修复成可移植的 vendor wheel / lazy clone 备选, 让 `pip install popolaloom` 在任意机器上能 0 错误装上; (2) 仿 [research §A.3-§A.5](../../research/v0.5.0-skill-install-lark-research.md) 实测的 DevolaFlow `devola-init` 833 行 dispatcher 引入 `popola init` Typer 子命令组 (含 `--mode={core,standard,full}` / `--global` / `--project` / `--list` / `--with-examples` 8 modifier), 把 SKILL.md 一次性 file-copy 到 4 个目标 IDE 的标准目录 (Cursor / Claude / Codex / Copilot, per [research §A.5 + §E.1.4](../../research/v0.5.0-skill-install-lark-research.md) per-target 表); (3) 编写一份 ~ 2800 token / ~ 11 KB 的 Anthropic-baseline 单文件 SKILL.md (per [research §B.1 + §B.3](../../research/v0.5.0-skill-install-lark-research.md) 选型, 推迟 DevolaFlow folder shape 到 v0.6.0), 包含 3-5 个快速参考示例 (`popola dispatch` / `popola list` / `popola attach --follow` / `popola cancel` / `popola status`) + 1 个 "supervised long-running task" 工作流 + MCP verb 链接; (4) 引入 `popola skill {install, doctor, upgrade}` 子命令组 (per [research §E.1.5](../../research/v0.5.0-skill-install-lark-research.md) 在 `evolution/` 模块上扩展 3 个 sibling), 让 PopolaLoom 可以"自管理"其在多个 IDE 上的注册状态; (5) 加 `popola doctor` 综合自检 verb (per [research §G.1 #7](../../research/v0.5.0-skill-install-lark-research.md), 仿 [research §A.6](../../research/v0.5.0-skill-install-lark-research.md) `devola-init-doctor`), 一次性审计 skill 安装 + daemon 启动 + lark-cli 可用 + ArkTower 迁移就位 + 多 IDE 配置正确, 让用户在 IDE 里通过 Skill 能可靠地把任务派发到 Cursor / Claude / Codex CLI agent, 并在派发后"通过 ID Trace 到当前进程"以及"随时 attach 进去". 总共在 v0.4.1 baseline 上新增 ~ 2200 src / ~ 1500 test / ~ 1800 docs ≈ 5500 行, 把 [spec §3.2](spec.md) 9 模块的 skill (0% → 80%) + cli (75% → 90%) + evolution (60% → 85%) 三个模块拉到 ≥ 80%, 完成 Phase 1 → Phase 2 的转场签名.

### 0.3 与 v0.4.x 的关键差异 (5 条)

1. **install 形态**: v0.4.x = `pip install popolaloom` 即可 (但 fresh container 上会因 `arktower @ file:///home/agent/reference/ArkTower` 硬路径 fail), 装完后用户必须手写 mcp.json 或 cursor.json 配置才能在 IDE 里使用; v0.5.0 = `pip install popolaloom && popola init` 两步 (per [research §E.1.3](../../research/v0.5.0-skill-install-lark-research.md) 推荐), 第一步可移植 (vendor / PyPI / lazy clone 三选一; 见 D5.7), 第二步自动 file-copy SKILL.md 到 4 个 IDE 目录 + 自动接 mcp.json (Cursor 项目级或全局级).
2. **Skill 注册化**: v0.4.x = PopolaLoom 没有自己的 SKILL.md (只有 `evolution/skill_inject.py:81-109` 检测 DevolaFlow 的 SKILL.md 是否存在用作 reinforcement), 用户在 IDE 里看不到 PopolaLoom 作为可发现 skill; v0.5.0 = 一份 ~ 2800 token / ~ 11 KB 的 PopolaLoom-自己的 SKILL.md, 走 Anthropic baseline 单文件形态, frontmatter 含 `name=popolaloom`, `description=Use when delegating long-running coding tasks to a local agent CLI ...` (per [research §B.5](../../research/v0.5.0-skill-install-lark-research.md) 推荐); 4 个 IDE (Cursor / Claude / Codex / Copilot) 自动发现 (per [research §B.4](../../research/v0.5.0-skill-install-lark-research.md) 文件系统扫描).
3. **多 IDE 覆盖**: v0.4.x = 仅 mcp/server.py 通过 stdio 给 Cursor / Claude 加 mcp.json, 用户必须手配; v0.5.0 = 4 个 target × global / project 2 scope (Cursor / Claude / Codex 三个支持 global, Copilot 仅 project 单文件 .github/copilot-instructions.md per [research §A.5](../../research/v0.5.0-skill-install-lark-research.md)), `popola init all --global` 一键到位; 不写 `~/.cursor/skills-cursor/` (Cursor IDE 自有 bundled catalogue, per [research §F.4](../../research/v0.5.0-skill-install-lark-research.md) 实证).
4. **自管理能力**: v0.4.x = `evolution/skill_inject.py` 仅做"检测 DevolaFlow SKILL.md 是否存在 + 把 Workflow Context prepend 到 L3 prompt", 不能 install / doctor / upgrade; v0.5.0 = `popola skill install` (在指定 IDE 注册 PopolaLoom) / `popola skill doctor` (检测 4 个 IDE 上的 PopolaLoom skill 状态) / `popola skill upgrade` (用 wheel-bundled SKILL.md 重写 on-disk SKILL.md, 类比 [research §A.7](../../research/v0.5.0-skill-install-lark-research.md) DevolaFlow `devolaflow plugins refresh`), 让用户每次 `pip install --upgrade popolaloom` 后能自动同步.
5. **CLI 入口数量**: v0.4.x = 1 个 console_script (`popola = popolaloom.cli.main:app`, per [pyproject.toml:62-64](../../../../pyproject.toml)) + 8 root verb + 2 子命令组 (`popolad` + `eval`); v0.5.0 = 仍 1 个 console_script (per D5.5 推荐, 不学 DevolaFlow 的 12 个 console_scripts 风格 — 装 PopolaLoom 时 wheel 不爆 12 个 bin/ shim), 但子命令组扩展到 5 个 (新增 `init` / `skill` / `doctor`, 对齐 [pyproject.toml `[project.scripts]`](../../../../pyproject.toml) 仅 `popola` 的设计). 用户体感: `popola init` / `popola skill install` / `popola doctor` 三条新命令是装完 PopolaLoom 后第一组要跑的命令.

5. **IDE config audit**: 4 IDE 标准目录 (Cursor / Claude / Codex / Copilot) skill file 是否落地 + frontmatter 是否合法 yaml.

输出 colored output (✓ green / ⚠ yellow / ✗ red), exit 0 当 5 项全 ✓ 或仅有 warn, exit 1 当任一 ✗ (No Silent Failures: 错误描述清晰, 不 catch + swallow).
