## Theme

v1.0.0 is the **first General Availability** release. It builds on the v1.0.0-pre.1 [Cloud Dispatch Clarity](#-1-stable-surface-baseline-pre1-q-1q-12) baseline (live-validated end-to-end against Cursor's REST `POST /v1/agents` schema, including a real PR generated by a self-hosted worker — see PR #28) and adds an **opt-in experimental Connect-RPC adapter** (path-B) so power users can drive Cursor's full advanced-control surface (`--mode`, `--max-mode`, `--effort`, `--time-budget`, `--long-running`, `--auto-proceed-after-plan`, `--preset`) that the public REST schema does NOT accept. Both transports flow through the same `popola dispatch` verb; the default REST path remains the stable surface that the v1.x SemVer commitment covers.

The 12 inherited design decisions live verbatim in [`./.local/.agent/active/v0.10.0-cloud-dispatch-clarity/DECISIONS.md`](.local/.agent/active/v0.10.0-cloud-dispatch-clarity/DECISIONS.md) (Q-1..Q-12). The 10 net-new design decisions for v1.0.0 GA live in [`./.local/.agent/active/v1.0.0-ga/DECISIONS.md`](.local/.agent/active/v1.0.0-ga/DECISIONS.md) (Q-13..Q-22). The full per-decision implementation delta lives in [`CHANGELOG.md` §[1.0.0]](CHANGELOG.md#100--2026-05-11).

## What's new in v1.0.0 GA (delta over v1.0.0-pre.1)

### `--model` first-class flag (Q-A1; path-A; REST-safe)

```bash
popola dispatch --cloud-target=self-hosted --worker-name=my-worker \
  --model gpt-5.5 \
  "Refactor the caching layer and add unit tests"
```

`popola dispatch --model <id>` is the discoverable form of the previously-stringly-typed `--cli-flag model=<id>` extras key. It is **only** consumed by `cursor-cloud` dispatches; non-cloud adapters get a soft WARN and the flag is dropped. When both `--model X` and `--cli-flag model=Y` are supplied, the explicit `--model` flag wins with a WARN (No Silent Failures). Empty `--model` (the default) preserves the v0.10.0 `"default"` model fallback so Cursor picks the recommended model for the user's plan.

### Path-B advanced controls (`--auth-mode=session-jwt`, **EXPERIMENTAL**)

v1.0.0 GA ships the full **scaffolding** for the Connect-RPC adapter that unlocks Cursor's advanced dispatch controls — fields the public REST schema does NOT accept. The path-B stack is delivered as importable, mock-tested code; the supervisor wiring through `popolad` is **deferred to a v1.0.x patch** (`BL-v1.0.x-supervisor-path-b`). Until that patch lands, dispatching with `--auth-mode=session-jwt` exits non-zero with a bilingual hint pointing at `--auth-mode=rest` (the stable fallback).

> **Stability commitment (Q-22)**: path-B is **NOT** part of the v1.x SemVer surface. The wire format is reverse-engineered from Cursor's `cursor-agent` binary protobuf descriptor and may change without notice. When Cursor changes the format, the path-B path raises `CursorCloudInternalError` with `error.hint` pointing at `--auth-mode=rest` as the supported fallback.

### Two new `docs/known-issues.md` entries (per [`feedback_for_v1.0.0-pre.1.md` §2](.local/feedbacks/feedback_for_v1.0.0-pre.1.md))

- §2.1 — **Cursor cloud auto-create-PR is occasionally flaky**: even when the agent successfully `git push`es the feature branch, the run may return `"No branch name available for PR creation"` and the PR is not opened. Workaround: `gh pr create --base main --head <branch>` to open it manually. Tracked as upstream-side flakiness with no PopolaLoom-side fix.
- §2.2 — **Self-hosted worker pushes to the dispatch-time branch**: the agent uses the worker's bound checkout's current branch as the commit + push target. Workaround: `git checkout -b <agent-task-branch>` BEFORE dispatching, OR use `--cloud-target=cursor-managed` (Cursor cloud VM auto-creates a feature branch).

Both entries are mirrored in [`docs/zh/known-issues.md`](docs/zh/known-issues.md).

## What's still inherited from v1.0.0-pre.1 (the stable surface)

The entire v1.0.0-pre.1 cloud-dispatch-clarity work is part of v1.0.0 GA's stable surface and is unchanged:

- **Env-shape pivot on `POST /v1/agents` (Q-2)** — `env: {type, name?}` + `workOnCurrentBranch:true` (replaces the v0.9.x `usePrivateWorker` / `labels` / `autoGenerateBranch` body shape).
- **`account_class` hard-fail gate REMOVED (Q-4)** — replaced by `_enforce_self_hosted_worker_exists()` (worker-existence pre-flight via `GET /v0/private-workers`).
- **`--cloud-target` / `--worker-name` Typer flags (Q-6)** — first-class self-hosted vs cursor-managed routing.
- **No silent local fallback (Q-7)** — when `--cloud-target=self-hosted` and the named worker is missing, popola exits 78 with a bilingual hint pointing at `popola cloud worker start`. NEVER silently re-routes to `--cli=cursor` local.
- **Init wizard learns `default_cloud_target` (Q-5)**.
- **GitHub-App pre-flight + catalog regex extension (Q-9)** — early refusal with friendly hint when the App is not installed for github.com URLs.
- **`AgentEnv` adapter API (Q-11)** — `CloudCursorClient.create_agent(env=...)` typed parameter.
- **Tier-4 release-gate live smoke (Q-12)** — `tests/cloud/test_real_cursor_cloud_env_shape_v0_10_0.py`.

The full pre.1 highlights, breaking-change checklist, and migration notes live in [`CHANGELOG.md` §[1.0.0-pre.1]](CHANGELOG.md#100-pre1--2026-05-11).

## Breaking changes

**v1.0.0 GA introduces ZERO new breaking changes** over v1.0.0-pre.1. The 4 inherited breaking changes from pre.1 (Q-2 env-shape pivot, Q-4 gate replacement, Q-7 no-fallback contract, Q-11 adapter API signature) keep their one-release deprecation window — removal stays scheduled for v1.1+ as planned in pre.1 DECISIONS.md.

If you upgraded from v0.9.x straight to v1.0.0 (skipping pre.1), please walk through the [pre.1 breaking-change checklist](CHANGELOG.md#breaking-changes) before tagging your CI green.

## Deprecations

The 5 inherited deprecations from v1.0.0-pre.1 are unchanged:

- `--cli-flag use_private_worker=true` and `--cli-flag labels='{"worker":"X"}'` — translated to `env={...}` with a `DeprecationWarning`; removal scheduled for v1.1+.
- `--cli-flag autoGenerateBranch=...` — translated to a no-op (the gateway rejects this field); use `--cli-flag work_on_current_branch=true` instead.
- `[cursor].account_class` field on `credentials.toml` and `--account-class` flag on `popola auth cursor set` — kept for one-release backward compat; one-time `WARN` on read; removal targets v1.1+.
- `[user_preferences].cloud_target_priority` list — replaced by `default_cloud_target` (single value); kept for one-release backward compat; the resolver no longer consults the list.
- `CloudCursorClient.create_agent(use_private_worker=..., labels=...)` keyword arguments — replaced by `env: AgentEnv | None = None`. **(Breaking — see above.)**
